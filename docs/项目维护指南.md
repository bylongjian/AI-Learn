# 学习咩 · 项目维护指南

这份指南说明文件该放在哪里、改动后检查什么，以及本次整理为什么这样做。目标是让新读者容易找到入口，也让清理代码时有依据，避免为了“看起来整齐”影响现有功能。

## 一、目录怎么维护

运行代码、项目说明、行为规范和历史证据各有位置。新增文件优先放到已有目录，不为一次小改动增加一套架构或流程。

| 位置 | 应当放什么 | 常见修改入口 |
| --- | --- | --- |
| `README.md` | 项目介绍、能力、快速运行与文档链接 | 面向第一次打开仓库的人 |
| `docs/` | 当前需求、方案、运行与维护指南 | 当前功能变更后同步说明 |
| `docs/验收记录/` | 可公开的阶段摘要与精选展示图 | 原始结果、调试截图和过程日志放 `.local/acceptance/`，不提交 |
| `backend/app/` | HTTP、数据模型、AI、业务服务和数据访问 | 参照[总方案](方案设计文档.md)找职责 |
| `backend/tests/` | 业务与集成回归；共用 fixture 放 conftest | 数据构造放 factories，业务断言放测试 |
| `backend/sql/`、`scripts/` | 数据库升级与手工开发工具 | 初始化入口 `python -m scripts.init_db` |
| `frontend/src/`、`config/` | 页面、状态、平台能力和构建配置 | 六个页面与业务模块保持现有位置 |
| `frontend/tests/` | 业务测试与微信构建 smoke | `.test.ts` 自动发现；smoke 单独运行 |
| `prototype/` | 可单独打开的模拟交互原型 | 修改 src 后重新 build |
| `openspec/` | 功能规范、进行中的变更和归档 | 功能变更沿用项目已有流程 |

`node_modules/`、`.venv/`、`dist/`、`backend/data/`、`.playwright-cli/`、`output/playwright/` 和 `.worktrees/` 已忽略。不要提交本机环境、密钥、数据库或临时调试脚本；已有用户文件和数据也不能在整理时直接删除。

## 二、代码洁癖自检

清理前先确认这段代码守的是哪条真实边界。外部响应、用户输入和旧缓存需要验证；内部已有类型约束的调用不要反复判空，也不要用通用异常捕获掩盖程序错误。

| 本次检查项 | 处理与理由 |
| --- | --- |
| 实现前的模块存在性探测 | 删除测试中的 find_spec、yield None 和重复“仓储不存在”断言；正常导入失败已能暴露问题 |
| 纯默认配置断言 | 删除一项只检查默认值的用例及四组框架字段范围用例；保留跨阶段预算之和不能耗尽请求预算的业务校验 |
| 测试夹带历史脚手架 | 共享 MySQL 和文档服务 fixture 集中到 conftest，统一释放资源，不再从其他测试模块导入 fixture |
| 注释中的死代码 | 删除生产构建配置里未启用的打包分析和预渲染示例，导出的配置保持不变 |
| 模型、微信与检索响应校验 | 保留，属于外部输入；格式重试、私网 URL 与日志脱敏都有真实回归 |
| 可选字段与迟到响应检查 | 保留，覆盖旧题库、无来源记录、账号切换、取消请求和云端恢复 |
| 数据库回滚与文件删除恢复 | 保留，覆盖并发结算、取消、处理中删除、重启和清理失败 |

本次未改 `backend/app/` 与 `frontend/src/` 的业务源码、接口、模型参数和依赖。没有发现可在本次范围内确定删除且不影响行为的业务分支，因此没有凭静态搜索批量删除判空或异常处理。

## 三、怎样选择测试

优先验证用户能观察到的行为，每个新增核心接口通常保留 2～3 个高价值场景。现有复杂流程中的不同故障、并发和恢复用例各有作用，不按“测试数量太多”机械删除。

| 测试组 | 主要覆盖 |
| --- | --- |
| 后端 API、generation、grounded_quiz、search | 出题、结构与依据审核、领域选择、资料不足和有界重试 |
| scoring、identity、wechat_login | 确定性判分、JWT、开发身份边界和第三方登录失败 |
| user_repository、user_api | 真实 MySQL、归属隔离、旧表升级和报告重复结算 |
| document_parser、documents、knowledge、rag、vectors | 四格式解析、临时文件清理、向量隔离与降级顺序 |
| 前端 auth、storage、cloud、history、services | 身份切换、缓存恢复、请求取消、来源和报告回看 |
| 前端 knowledge 与 navigation | 上传/删除交错、轮询、账号隔离、导航防重与重试 |
| 微信 startup / wxss smoke | 真实构建产物 App/Page 注册、RAF 和原生样式编译 |

### 后端完整检查

在 `backend/.env.test` 中配置独立数据库与专用账号，数据库名必须以 `_test` 结尾；不要复制应用数据库名。fixture 会清理这个测试库中的五张业务表，不能与应用数据共用，也不要并发运行共享该库的测试。

```powershell
# 在 backend/ 执行
./.venv/Scripts/python.exe -m pytest -q --tb=short
./.venv/Scripts/python.exe -m pip check
```

测试账号需要目标测试库的建表、读写和 ALTER 权限；pytest 会完成测试库初始化。外部模型、检索、微信和向量化 HTTP 使用替代响应；MySQL 和临时 Chroma 使用真实实现。

没有测试数据库时，可以先执行以下不依赖数据库的单元/API 子集，但不能据此宣称完整回归通过：

```powershell
./.venv/Scripts/python.exe -m pytest -q tests/test_api.py tests/test_generation.py tests/test_grounded_quiz.py tests/test_scoring.py tests/test_search.py tests/test_public_urls.py tests/test_identity.py tests/test_wechat_login.py tests/test_knowledge_models.py tests/test_document_parser.py tests/test_vectors.py tests/test_rag.py
```

### 前端和原型检查

业务测试和类型检查不依赖运行中的后端。两个微信 smoke 则读取实际构建产物，必须在构建之后执行；WXSS 编译器路径按本机安装位置调整。

```powershell
# 在 frontend/ 执行
npm.cmd test
npm.cmd run typecheck
npm.cmd run build:h5
npm.cmd run build:weapp
node tests/weapp-startup-smoke.cjs
node tests/weapp-wxss-smoke.cjs 'D:/微信web开发者工具/resources/app.asar.unpacked/node_modules/wcc-exec/wcsc.exe'
```

原型独立维护：在 `prototype/` 运行 `npm.cmd test`。本次没有修改原型内容，不重新生成 HTML。
