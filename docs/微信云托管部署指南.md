# 学习咩后端 · 微信云托管 Docker 部署说明

本次为现有 FastAPI 后端生成容器构建文件，不改变接口、业务代码或依赖版本。构建目标目录使用 `backend/`，默认监听 `0.0.0.0:80`；平台端口填写 80，真实密钥在运行时配置，不打入镜像。

本文通过 Context7 查询微信官方文档，并核对腾讯云官方平台说明。已生成文件不等于已经构建成功或完成云端发布；本机没有可用 Docker，本轮不执行付费云部署。

## 一、官方要求与本仓处理

先区分平台要求和本项目的实现选择。Python 版本、镜像分层和单 worker 是针对本仓的选择，不把官方旧示例中的 Alpine、Flask 或 Python 3.8 当作平台强制要求。

| 核对项 | 官方说明与本仓处理 |
| --- | --- |
| Dockerfile 位置 | 放在目标目录根部；本仓为 `backend/Dockerfile`，使用仓库构建时目标目录填 backend |
| 网络监听 | 微信官方 Python 示例监听 `0.0.0.0`；本仓也监听全部容器接口，避免只监听回环地址 |
| 端口一致 | 应用实际监听与部署设置一致；本仓默认 `PORT=80`、`EXPOSE 80`、Uvicorn 80，修改时须同步平台配置 |
| 启动命令 | 只保留一条最终 CMD；使用 exec 启动 Uvicorn，便于进程退出时清理资源 |
| 构建效率 | 先复制 requirements 并安装，再复制代码；本仓用独立依赖阶段，沿用 Python 3.11 锁文件 |
| 运行配置 | 平台运行时传入配置；不在构建步骤连接数据库、不在构建时请求 AI、不复制真实 env |

微信官方依据：[Python 自定义部署](https://developers.weixin.qq.com/miniprogram/dev/wxcloudservice/wxcloudrun/src/quickstart/custom/python)、[构建效率优化](https://developers.weixin.qq.com/miniprogram/dev/wxcloudservice/wxcloudrun/src/scene/build/speed)。目录、单监听端口与运行环境变量的补充说明见[腾讯云服务设置](https://cloud.tencent.com/document/product/1243/77197)。

微信文档采用 `PORT` 环境变量并提供 80 的默认值。本仓在 Dockerfile 中显式设置默认值，不依赖平台一定自动注入该变量；`EXPOSE` 只是镜像端口声明，不能替代实际启动监听和平台端口配置。

## 二、生成的两个文件

Dockerfile 使用 Debian 系的 `python:3.11-slim-bookworm`，与当前 Python 3.11 依赖保持一致。HTTPS 证书和原生向量依赖的运行库在镜像中安装；没有引入 Nginx、Gunicorn、数据库服务或 OCR。

| 文件 | 作用 |
| --- | --- |
| [backend/Dockerfile](../backend/Dockerfile) | 安装锁定依赖，复制 app、SQL、初始化入口，启动单 worker Uvicorn并提供镜像健康检查 |
| [backend/.dockerignore](../backend/.dockerignore) | 只允许构建所需输入，排除真实 env、data、虚拟环境、测试、日志和本机资料 |

本仓初始化程序需要 `sql/` 和 `scripts/init_db.py`，因此与直接排除整个 sql/scripts 的示例不同，这两个输入必须保留。镜像启动不会自动建库建表，不会在每次扩容或重启时重复执行迁移。

分阶段复制、构建上下文和忽略规则另按 [Docker 多阶段构建](https://docs.docker.com/build/building/multi-stage/)与[构建上下文说明](https://docs.docker.com/build/concepts/context/#dockerignore-files)核对；这些是 Docker 的机制，不是微信平台额外要求。

默认使用腾讯云 HTTPS PyPI 镜像加快下载，未设置 trusted-host 绕过 TLS 校验。需要换回公共 PyPI 时，构建增加 `--build-arg PIP_INDEX_URL=https://pypi.org/simple`；不要通过构建参数传入模型或数据库密钥。

## 三、本地构建与基本验收

本地构建是可选步骤。若 PowerShell 提示“无法将 docker 项识别为 cmdlet、函数、脚本文件或可运行程序”，说明终端找不到 Docker 命令，尚未开始读取 Dockerfile。通常是没有安装 Docker，或安装后当前终端尚未更新 PATH；无需因此修改 Dockerfile。

可以直接按下一节使用云托管的代码构建：仓库构建目标目录填 `backend`，Dockerfile 文件名填 `Dockerfile`，服务端口填 `80`。腾讯云官方将[本地构建镜像](https://cloud.tencent.com/document/product/1243/49240)列为可选步骤。

需要先在本机验证时，按 [Docker Desktop Windows 安装说明](https://docs.docker.com/desktop/setup/install/windows-install/)安装并启动 Docker Desktop，使用 Linux 容器，重新打开 PowerShell 后检查：

```powershell
docker --version
docker version
```

第一条检查终端能否找到 Docker；第二条应同时显示 Client 和 Server，确认容器引擎可连接。如果只显示 Client 并提示无法连接，请先确认 Docker Desktop 已启动，再根据具体错误排查。

有 Docker 后，在项目根目录执行以下命令。构建上下文必须是 `./backend`，不能只指定 Dockerfile 路径却把整个仓库当作上下文。

```powershell
docker build -t ai-learn-backend:local ./backend
docker run --rm --name ai-learn-backend -p 8000:80 ai-learn-backend:local
```

另开终端访问 `http://127.0.0.1:8000/api/v1/health`，应返回 `code=0`、`data.status="ok"`；`http://127.0.0.1:8000/docs` 应能打开。没有配置 Key 或数据库时，这只证明应用能启动，不证明出题、账号和知识库均可用。

停止验证容器时执行 `docker stop ai-learn-backend`。需要测试其他容器端口时，显式设置 PORT 并对应映射，例如 `-e PORT=8080 -p 8000:8080`；正式平台也要填写对应监听端口。

Dockerfile 的 HEALTHCHECK 使用 Python 标准库请求本机健康接口，不额外安装 curl。它用于 Docker 镜像检查；平台自身的探活按控制台能力另行配置，不能假定平台一定采用该指令。

## 四、微信云托管填写与配置

选择“有 Dockerfile”的代码构建方式。只提供 backend 所需源码；手工上传 ZIP 时也应先排除真实 env、data、虚拟环境和测试，不要把本机整个 backend 目录直接压缩上传后才依赖忽略规则。

| 设置 | 本仓填写方式 |
| --- | --- |
| 构建目标目录 | 仓库构建填 backend；只上传 backend 内容时使用上传包根目录 |
| Dockerfile 文件名 | Dockerfile |
| 服务监听端口 | 80；与 PORT 和 Uvicorn 对应 |
| 后端环境 | APP_ENV=production，DEV_LOGIN_ENABLED=false |
| 模型与检索 | DEEPSEEK_API_KEY；按功能配 TAVILY_API_KEY、DASHSCOPE_API_KEY 和匹配的 DASHSCOPE_BASE_URL |
| 账号与云端记录 | 云数据库 MYSQL 配置和私有 JWT_SECRET，不使用容器内 localhost 代替云数据库地址 |
| 微信登录 | 配置匹配真实小程序的 WECHAT_APP_ID、WECHAT_APP_SECRET |
| H5 跨域 | CORS_ORIGINS 使用实际 H5 来源，按配置要求填写 JSON 数组 |
| 日志 | 使用标准输出，不在容器内积累历史日志文件 |

正式数据库创建并连通后，在具备相同云端环境变量和网络的受控迁移终端执行 `python -m scripts.init_db`。它会读取平台注入的配置并完成现有 SQL 升级；不要在 Dockerfile RUN 或每次容器启动时自动运行，也不要携带本机 `.env.test`。

## 五、知识库不能靠镜像解决的存储问题

官方迁移文档要求服务不依赖单个容器节点的本地状态。容器可能被替换或扩缩容，本地文件不能视作可靠持久化数据；这是平台运行特性，不能通过 Dockerfile 中的 mkdir 或 VOLUME 声明解决。[官方迁移说明](https://cloud.tencent.com/document/practice/1243/49230)

当前项目的文档片段和向量存储在本地 Chroma，默认镜像目录是 `/app/data/chroma`。这些数据对既有知识库必需，不能作为可丢弃缓存；`/app/data/uploads` 仅供临时处理。没有落实可靠存储方案前，知识库不应按生产可用能力对外承诺。

保持一个 Uvicorn worker 仅解决同一实例内的并发写入约束，不能解决多个云实例各自拥有不同 Chroma 数据的问题。把最小、最大实例数都设为一，也不能保证实例替换或重新部署后本地数据仍在。

知识库正式上线需要另行设计并验证平台支持的持久化方案或远程向量存储，以及后台任务恢复。不要直接把 SQLite/Chroma 工作目录放到未经兼容性验证的共享文件系统上；本次不更换存储实现、不删除现有数据。

2026-10-30 本轮先保存容器配置与源码，持久化改造暂缓，留待后续迭代。当前实现仍存在上述数据丢失风险，暂缓不等于已经解决，也不能据此标记知识库已完成生产验收。

### 对象存储可以解决哪部分问题

COS 可以保存文件和备份，但不能直接替代本仓当前 Chroma 的运行目录。本仓使用 `chromadb.PersistentClient(path=...)`；单节点 Chroma 会在目录中维护 SQLite 数据库和向量索引，而 COS 通过对象接口读写文件。根据两者的存储方式，不能通过把 `CHROMA_PERSIST_DIR` 改成 COS 地址来完成迁移。[Chroma 存储说明](https://cookbook.chromadb.dev/core/storage-layout/)、[COS 接口说明](https://cloud.tencent.com/document/product/436/7751)

| 数据 | 上线后的存储方式 |
| --- | --- |
| 上传的 PDF、DOCX 等原文件 | 如需长期保留，可放私有 COS；当前实现解析后清理临时原文件，保留原件需要另行改动 |
| Chroma 备份 | 可以放 COS，但须制作一致的备份；直接复制正在写入的目录不能保证可恢复 |
| 在线检索的片段、向量和索引 | 使用具备可靠持久化的独立 Chroma 服务，或适配远程向量数据库 |
| 用户、测验、报告和文档状态 | 继续使用 MySQL，COS 不替代这些数据库读写 |

沿用 Chroma 时，可以将 FastAPI 与有持久化磁盘的 Chroma 服务分开部署，再将本仓客户端改为 `HttpClient`。仅把 Chroma 放进另一个同样使用临时磁盘的容器仍会丢数据；远程服务还需要配置访问控制和备份。该方案需要调整客户端和配置，当前 Dockerfile 尚未实现。[Chroma 官方客户端与服务端模式](https://docs.trychroma.com/docs/run-chroma/client-server)

不要把“启动时从 COS 下载整个库、退出时上传整个库”当作生产持久化方案：异常退出时可能来不及上传，多实例写入也会互相覆盖。

## 六、本轮验证边界

本轮核对 Dockerfile 指令、启动及健康检查命令、COPY 输入和忽略规则，确认未修改业务源码、真实配置、SQL 和依赖。当前终端未检测到可用的 Docker 命令，因此尚未执行镜像构建、Linux 依赖安装、容器启动或云端探活，不能把静态检查写成镜像已经可运行。

| 检查 | 实际结果 |
| --- | --- |
| Dockerfile 静态检查 | 18 条指令，JSON 命令与 shell 语法通过，PORT/EXPOSE/单 worker 一致，文件为无 BOM 的 UTF-8 和 LF |
| 复制输入 | app、锁文件、三份 SQL 和 init_db.py 存在；没有 COPY 整个上下文或构建时运行迁移 |
| 忽略规则样例 | 通用忽略解析器的 7 个必需输入、15 个私有/生成文件样例通过；该检查不等同于 Docker 引擎实际处理上下文 |
| 现有健康接口测试 | `pytest -q tests/test_api.py::test_health_envelope_without_api_key`：1 passed，未配置 Key 仍可返回健康结果 |
| 文档、提交边界与只读审查 | 本地链接可解析，密钥/本机数据未进入候选，审查未发现 Critical 或 Important 问题 |
