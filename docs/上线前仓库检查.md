| --- | --- | --- |
| 后端环境 | 本机为 development，开发登录已开启 | `APP_ENV=production`、`DEV_LOGIN_ENABLED=false`，确认开发登录接口不可用 |

## 二、哪些文件提交，哪些留在本机

源码仓库应能重新安装、构建和测试，因此测试代码、固定样本与锁文件有保留价值。真实运行数据、个人配置和一次性结果另外存放。

| 文件或目录 | Git 提交 | 实际部署 | 处理说明 |
| --- | --- | --- | --- |
| `backend/app/` | ✅ 保留 | ✅ 后端必需 | API、资料、模型、计分和存储代码 |
| `backend/sql/`、`backend/scripts/init_db.py` | ✅ 保留 | ✅ 迁移包必需 | 是建表升级定义，不是数据库导出；不能忽略全部 `.sql` |
| `backend/requirements.in`、`requirements.txt` | ✅ 保留 | 锁定依赖用于安装 | 本次不改版本或直接删包 |
| `backend/tests/`、`frontend/tests/` | ✅ 保留 | 不放运行包 | 业务与平台回归；不因准备上线就删除测试源码 |
| 两端 `tests/fixtures/` | ✅ 保留 | 不放运行包 | 固定测试样本，不是真实用户记录，不要一并排除 |
| `backend/tests/conftest.py` | ✅ 已保留 | 不放运行包 | 共享 fixture 已随仓库整理提交，后续调整测试时一起维护 |
| `frontend/src/`、`config/`、`types/` | ✅ 保留 | 构建输入 | 线上交付对应产物，不能用源码归档代替小程序包 |
| `frontend/package.json`、`package-lock.json` | ✅ 保留 | 构建时必需 | 用 `npm ci` 还原版本，不删除锁文件后随意安装最新依赖 |
| `frontend/src/package.json` | ✅ 保留 | 构建输入 | 指定该目录 ESM 类型，不是应删的重复 package 文件 |
| `frontend/project.config.json` | ✅ 保留 | 微信项目配置 | AppID 不是 AppSecret；正式发布需有效 AppID，个人配置另放 private 文件 |
| `.env.example` | ✅ 保留 | 配置参考 | 空密钥的字段说明，不是可直接使用的生产凭据 |

| `docs/验收记录/` | ✅ 保留摘要和三张图 | 不放运行包 | 完整记录转存 `.local/acceptance/` |
| `prototype/`、`docs/UI原型图.png` | 🔧 学习项目可保留 | 不放运行包 | 参考项目也保留原型；ZIP 副本不必重复提交 |
| `.github/`、`openspec/` | ✅ 维护资料保留 | 不放运行包 | 已有技能、提示词和规范，不是服务器运行依赖 |
| `.gitattributes`、`.editorconfig`、lint/TS 配置 | ✅ 保留 | 按构建需要使用 | 区别于本机 IDE 状态 |
| 真实 `.env`、`.env.test`、前端 `.env.production` 等 | ⛔ 不提交 | 平台注入或受控配置 | 不随源码公开，不以示例 Key 代替真实配置 |
| `backend/data/`、真实 MySQL 数据及导出备份 | ⛔ 不提交 | 独立持久化与备份 | 也不能为了清理目录直接删除 |
| `.local/`、`.scratch/`、各模块 `.qa/` | ⛔ 不提交 | 不放发布包 | 原始验收、临时脚本与过程资料 |
| `.playwright/`、`.playwright-cli/`、`output/playwright/` | ⛔ 不提交 | 不放发布包 | 浏览器快照、操作脚本与联调响应；旧快照可清理 |
| `.venv/`、`node_modules/`、缓存、coverage | ⛔ 不提交 | 安装或构建生成 | 不复制本机虚拟环境到服务器 |
| `frontend/dist/` | ⛔ 通常不提交 Git | ✅ 对应前端发布包 | 选择 weapp 或 h5，使用正式配置重新构建 |

## 四、密钥、Git 状态和历史检查

检查只输出路径、是否已配置和计数，不记录密钥、密码或用户文档正文。除了忽略规则，还核对实际 Git 候选，避免文件早已被跟踪却误以为加规则就足够。

| 检查 | 结果与范围 |
| --- | --- |
| 当前凭据是否出现在候选源码 | 对本机配置中 7 个长度至少八字符的 Key、Secret、密码精确匹配，未发现命中 |
| 当前文本中的明显凭据格式 | 私钥头、API Key 和 JWT 形状未命中；未对截图做 OCR |
| Git 历史中的当前凭据 | 本地 refs 可达的 566 个 blob 未命中上述值；不覆盖未知旧密钥或未抓取的远程历史 |
| 忽略规则与已跟踪文件冲突 | 最终检查要求为零；真实 env、data 与私有目录不得出现在提交候选 |
| 旧验收文件 | 旧路径删除应随本次提交一起提交；本次转存不抹去旧 Git 提交中的资料，也不重写历史 |
| 暂存区 | 检查时为空；未执行 add、commit 或 push |

将来若发现真实密钥曾提交，需处理密钥本身及历史暴露范围，仅加 `.gitignore` 不够。本次没有发现上述当前凭据命中，也没有擅自轮换密钥或修改已发布历史。

## 五、本地数据该存在哪里

运行数据关系到账号、文档和历史恢复，不能当作普通垃圾移动。一次性测试记录可以归档，而正在使用的数据库和文件目录应保持稳定。

| 数据 | 位置 | 本次处理 |
| --- | --- | --- |
| 应用配置 | `backend/.env`、`frontend/.env` | 本机保留，不提交，不复制为正式配置 |
| 测试连接 | `backend/.env.test` | 忽略；数据库名有 `_test` 后缀，与应用库不同 |
| MySQL 测试数据 | 独立测试库 | 只读确认，不删除；fixture 仅可清理这个库 |
| 开发账号、题库与报告 | 本机应用库 | 正式环境用独立库；清除本机文件不等于清除数据库记录 |
| 文档片段与向量 | `backend/data/chroma/` | 保持原位并忽略，不能当作无用缓存删除 |
| 上传临时文件 | `backend/data/uploads/` | 由应用生命周期管理，不在处理中手工搬走 |
| 原始验收资料 | `.local/acceptance/` | 已整理，不提交 |
| 导出备份 | 受控备份位置；本机可用 `.local/backups/` 暂存 | 本次未导出，不把用户数据复制进公共文档 |

MySQL 与 Chroma 需配套备份恢复，备份前停止业务写入。只复制其中一份或热拷正在写入的 SQLite 文件，不能作为已经验证可恢复的方案。

## 六、源码提交与发布包分别怎么选

`.gitignore` 不决定 ZIP、Docker 或云平台上传什么。不要直接压缩整个工作目录上传，那可能连同 `.local/`、真实 `.env` 和运行数据一起打包。

| 交付物 | 应包含 | 应排除 |
| --- | --- | --- |
| 源码提交 | 源码、测试、锁文件、迁移、文档和必要图片 | 真实 env、原始验收、缓存、备份和私有目录 |
| 后端运行及迁移包 | app、锁定依赖、启动配置；迁移所需 sql 和 init_db.py | env、data、.venv、测试、旧样品、原型和整个仓库 |
| 微信小程序包 | 正式地址、真实 AppID、关闭测试登录后构建的 `frontend/dist/weapp` | H5 产物、源码归档、日志和后端密钥 |
| H5 静态包 | 正式地址、关闭测试登录后构建的 `frontend/dist/h5` | 微信产物和本机工具；H5 本身没有正式网页登录入口 |

本仓现已新增 Dockerfile 和 `.dockerignore`，仍不代表实际部署已通过。与参考仓排除 sql/scripts 的写法不同，本仓镜像保留 SQL 和初始化入口，确保显式迁移所需文件齐全。

当前后端依赖锁也包含测试工具，后续可再分生产与开发依赖；本次没有为了体积而删包或改锁文件。部署目标已确定为微信云托管，实际镜像构建、生产持久化和正式凭据配置仍待验证。

## 七、提交和上线前的验收步骤

先核对提交边界，再在正式参数下构建和体验。历史自动化结果不能替代正式环境验收。

| 步骤 | 你要做什么 | 应该看到什么 |
| --- | --- | --- |
| 1 | `git status --short` | 源文件变更和旧记录删除可见；不出现 .local、env、data、node_modules 或 dist |
| 2 | `git ls-files -ci --exclude-standard` | 无输出，没有已跟踪文件与忽略规则冲突 |
| 3 | 自行选择文件加入暂存后检查 `git diff --cached --name-status` | 新增 conftest、文档与三张图齐全；原始记录删除，私有资料未加入 |
| 4 | 查看实际 diff，必要时用 `git diff --ignore-space-at-eol` 区分换行 | 业务源码、SQL、锁文件未被本次整理改变 |
| 5 | 按维护指南测试，并用正式配置重新构建 | 检查通过、请求正确 API，测试登录入口关闭；H5 跨域预检与实际请求均成功 |
