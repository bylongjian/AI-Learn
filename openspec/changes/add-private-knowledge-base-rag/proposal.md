# Proposal

## Why

用户已经能围绕主题、网页和粘贴的正文闯关，但还不能把自己的课程讲义、培训资料直接导入。此次参照 `archive/2026-07-22-add-knowledge-base-rag/` 的产品范围，为当前版本补上私有文档知识库，并把用户确认的“文档检索 → 联网补充 → 模型兜底”写成可验收的规则。

## What Changes

本次让用户从“我的知识库”上传资料，看到处理结果，再选一篇就绪文档开始闯关。归档是需求参考，接口、存储和前端接入位置都以当前代码为准。

- 支持 PDF、DOCX、Markdown、TXT；必须登录，每人最多 10 篇、单篇最多 10MB，不设每日次数额度；扫描 PDF 不新增 OCR。
- 新增文档上传、后台解析和向量化、处理状态、列表与删除。后台处理最多 180 秒；原文件在解析结束后清理，仅保留记录和检索片段。
- 微信小程序和 H5 均支持上传；从“我的”进入知识库，处理中的文档不能出题，就绪文档可发起现有闯关流程。
- 在现有 `POST /api/v1/quiz/generate` 增加可选 `doc_id`。文档检索与联网补充共用 25 秒，完整出题请求仍最多 55 秒，不恢复归档中当前不存在的异步出题接口。
- 文档资料足够时按文档出题；不足或检索失败时尝试联网补充；仍无充分资料时按用户要求使用模型知识继续出题。权限错误、文档未就绪、内容违规和保存失败不触发此降级。
- **BREAKING（规范行为）**：为文档出题明确允许模型兜底；兜底题库标注“模型生成，未依据文档或联网资料核实”，保存降级原因，不伪造引用。未传 `doc_id` 的普通出题继续遵循现有资料充分性和逐题依据检查要求。
- 删除文档清除检索片段；已经生成的题库、报告及引用摘录继续保留。清理尚未完成时明确展示状态，不把部分删除伪装成全部成功。

### 已确认的需求小卡

提案先经人工确认，再进入实现。首个样品展示“登录 → 上传一篇中文 TXT → 就绪 → 五题闯关”，并单独演示检索故障时的模型兜底标识。当前用户已确认样品布局和提示，并授权 Playwright 自行验收；代码、自测、真实云端联调和代理体验验收已完成，详见 [tasks.md](tasks.md)。规范同步与归档等待用户最终确认。

| 最重要的预期 | 怎么判断做对了 |
| --- | --- |
| 私有资料能导入 | 四类文件可上传，列表有处理结果，超过额度明确拒绝 |
| 只用自己的指定文档 | 跨账号不可读，同账号另一篇文档也不混入检索 |
| 出题失败有明确去向 | 按文档、联网、模型的顺序处理，并展示实际使用方式 |
| 等待有上限 | 文档处理 180 秒；资料准备 25 秒；完整出题 55 秒 |
| 历史记录可解释 | 重开题库或报告仍有来源或兜底提示；删除文档不删除历史 |

## Capabilities

这些能力已经存在于主规范，因此本次提交修改规范的差量，不把同一能力再命名为新功能。主规范目前描述了部分尚未接入当前代码的 RAG 行为，本次同时明确落地范围。

### New Capabilities

无。

### Modified Capabilities

- `knowledge-base-documents`：落实上传与私有隔离，补齐双端入口、180 秒处理、原文件清理、重启恢复和可重试删除规则。
- `knowledge-base-quiz-generation`：接入当前同步出题接口，规定文档优先的工具调用顺序、联网与模型兜底，以及真实来源和降级信息的保存。
- `web-search-context`：限定原有严格资料要求的适用范围，并为带 `doc_id` 的请求声明明确且可见的模型兜底例外；普通出题保持当前要求。

## Impact

后端新增轻量文档解析、Embedding 调用、Chroma 存储和知识库路由；复用当前身份、MySQL、DeepSeek、出题和报告主流程。前端扩展来源类型、上传网络调用、知识库页面和降级提示。

| 范围 | 主要变动 |
| --- | --- |
| 后端接入 | `app/routes/knowledge.py`、文档相关模型和服务；修改 `routes/api.py`、`services/quiz.py`、`main.py`、`core/config.py`、`core/middleware.py` |
| 数据 | 新增 `kb_documents` 表；题库保存可空 `generation` 信息，扩展现有 `reference` JSON 中的文档来源 |
| 接口 | 新增 `/api/v1/knowledge/documents` 的 POST/GET 和 `/{doc_id}` 的 GET/DELETE；现有出题请求可选传 `doc_id` |
| 前端 | 新增 `pages/knowledge/index` 和“我的”入口；扩展 API、账号切换清理、来源展示及本机/云端恢复校验 |
| 直接依赖 | 新增 `chromadb`、`pypdf`、`docx2txt`、`python-multipart`、`langchain-text-splitters`；Embedding 使用已有 `httpx` 调用百炼 OpenAI 兼容接口 |
| 运行方式 | 本期使用本地 Chroma 和一个后端 worker，配置持久化目录、百炼模型/地域地址/密钥；不引入 COS、生图、Redis 或独立任务队列 |
| 兼容要求 | 保留旧题库读取、确定性计分、XP 结算、游客普通学习与现有主页面导航；新旧前端需配套发布 |

本次不会改业务实现、调用付费模型做真实验收、提交、推送或发布。提案通过人工确认后，另行进入实施。
