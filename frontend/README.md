# 学习咩小程序前端

使用 Taro 4.3.1 官方默认脚手架生成，React 18 + TypeScript + Webpack5。页面与图标依据仓库 `prototype/`，未添加新的设计方向。

## MVP 功能

包含输入、答题、报告、题库和“我的”五页。支持单选/多选/判断、提交后讲解与XP、退出恢复、报告失败重试、题目回看、题库搜索筛选、个人统计，以及账号云端题库和报告。实际验收结果与尚未验证事项见 [用户系统验收记录](../docs/用户系统验收记录.md)。

## 本地运行

在本目录执行：

```powershell
npm.cmd ci --registry=https://registry.npmjs.org
Copy-Item .env.example .env
npm.cmd run dev:h5
```

复制配置前检查 `.env` 是否已存在；存在时保留并修改，不覆盖。默认后端为 `http://127.0.0.1:8000`，H5 预览为 `http://127.0.0.1:10086`。

真实后端启动见 `../backend/README.md`。DeepSeek Key 只保存在后端 `.env`；前端配置只有 API 地址和 AppID。修改前端环境变量后重新编译。

## 出题领域确认与来源

正常使用时，首页支持学习主题、公开网页链接和完整正文。后端发现同名概念存在歧义时，展示简短领域选项；选择后重新检索对应领域，再出题。资料不足时保留输入，提供重试和补充资料入口，不退回纯模型猜题。

首个模拟样品复用实际页面和后端流程，只替换外部检索与模型边界，不访问数据库，也不调用付费 API。它用于确认交互，不能证明新知识的准确性。

先在 `frontend` 构建 H5，再在 `backend` 执行：

```powershell
./.venv/Scripts/python.exe -m scripts.quiz_sample
```

打开 `http://127.0.0.1:8000`，页面顶部显示黄色“模拟交互样品”提示。输入 `Harness Engineering` 可以体验领域选择；输入 `模拟资料不足` 可以体验暂停和返回修改。关闭样品服务后，再按后端 README 启动真实服务。样品与真实后端不能同时占用 8000 端口。

用户已确认首个样品流程可以继续。完整功能现在支持在每题讲解下展开来源，查看片段、日期及网页链接，并复制链接；复制失败会提示重试。网页来源未提供发布日期时如实显示，正文来源明确标记“未独立联网核实”。

新题库的可选 `reference` 包含 `topic/retrieved_at/sources/question_sources`，与后端详情结构相同。来源随游客本机记录或登录账号的云端题库保存，刷新重开仍保留；云端详情可为本机进度补齐来源。旧题库不清理，继续答题并显示“本次记录未保存参考来源”。后端升级需先执行其 README 中的初始化命令。

要演示网页来源，模拟样品输入 `模拟网页来源`，选择领域并作答后展开参考来源。其链接为示例地址，不能用于判断真实检索质量。真实服务的验收结果和待确认项见 [AI 出题优化验收记录](../docs/AI出题优化验收记录.md)。回滚时前后端配套回退，保留本机缓存和数据库新增列，不清空旧记录。

## 小程序构建

```powershell
npm.cmd run build:weapp
```

用微信开发者工具导入本目录的 `project.config.json`，它指向 `dist/weapp`。默认 AppID 是 touristappid；真机和正式环境需配置自己的 AppID、手机可访问的后端地址及对应微信合法域名。微信系统状态栏和胶囊使用平台能力，H5 中的状态栏只用于原型对照。

## 页面切换与报告回看

微信的“闯关、题库、我的”改用平台 Tab 页缓存切换，保留原有底栏外观，避免每次都销毁并重建页面。首次进入仍需平台加载；已访问页面的重复切换会复用页面实例。相关配置按 [Taro 自定义 TabBar](https://docs.taro.zone/docs/custom-tabbar) 实现，H5 的路由方式保持原样。

内容区域使用 240 毫秒左右整页滑入，不使用上下位移或淡入。动画只在实际页面切换时播放，不重挂载表单和学习内容；普通数据更新不重播，在支持“减少动态效果”的环境中会关闭。出题、计分、登录和保存没有因动画改变。缓存页离开时仍取消失效请求，账号切换不会沿用其他账号的编辑界面。

完成关卡后，在报告中点击“回看本轮题目”，每题讲解下也能查看与复制来源；旧题库显示未保存来源提示。导航失败会提示重试，并允许下一次正常切换，不留下未处理的跳转错误。

## 测试与检查

```powershell
npm.cmd test
npm.cmd run typecheck
npm.cmd run build:h5
npm.cmd run build:weapp
node tests/weapp-startup-smoke.cjs
```

核心自动化测试 67 项通过，覆盖学习闭环、领域确认、来源恢复、账号隔离、云端历史、报告导航防重与故障重试。测试替换外部请求，不消耗模型额度。skipLibCheck 只跳过 Taro 等依赖的跨平台声明检查，业务源码仍参与检查。

公共按钮按下后立即显示点击态，松开后恢复；首页、题库和我的报告入口会显示“正在打开报告”，避免等待期间反复点击。导航失败时关闭等待提示并允许重试，原有报告读取、计分和返回位置保持不变。实现按 [Taro Button](https://docs.taro.zone/docs/components/forms/button) 和 [hideLoading](https://docs.taro.zone/docs/apis/ui/interaction/hideLoading) 的官方接口处理，界面反馈与实际页面初始化耗时分别验收。

微信实际入口已复验：快速双击只打开一份报告，提示接口和导航异常后仍可真实重试，没有运行时异常。两次缓存报告的原生节点就绪约为 2.01、2.39 秒；这不是明显加速的证明。临时样品与观察钩子已移除，详情见 [点击复验](../docs/qa/click-latency-verified.json) 和 [首页恢复结果](../docs/qa/click-ui-restored.json)。

2026-10-29 实际微信模拟器验收发现，快速连续勾选多选题时旧状态会覆盖前面的选择。已改为基于最新状态更新选择集合，判分规则不变；真实五题验收再次得到 80% / 40 XP，报告回看五条来源入口齐全，运行时异常为 0。写法依据：[React 18 状态更新说明](https://18.react.dev/reference/react/useState#updating-state-based-on-the-previous-state)。本轮使用真实模型与官方文章，结束后移除临时题库，未清理用户原有记录。

小程序生产构建后必须运行启动 smoke：它直接加载 `dist/weapp` 的真实入口与拆分模块，检查 App、首页 Page 能注册，并检查 Taro 的 RAF 定时器与取消能力。仅 Webpack 显示 `Compiled successfully` 不足以证明应用可以启动；此检查也不能替代微信开发者工具或真机验收。

Taro 4.3.1 在当前构建环境中会向自身 RAF 实现注入 runtime 总出口，导致 App 注册前出现循环依赖的初始化错误。仅微信构建通过官方 `mini.webpackChain` 加载精确模块 guard，阻止 `runtime/dist/bom/raf.js` 内两个 RAF 标识符的自注入；其他模块的全局注入、runtime 原有定时器回退以及 H5 配置均保留。无需修改 `node_modules`。

## 数据边界与登录

游客的题库、作答与报告保留在当前设备。登录后，后端保存该账号生成的题库和完成的报告；首页显示真实昵称、累计 XP 和最近报告，“我的”和题库支持云端分页，题库的关键词和状态筛选由服务端执行。清除设备数据后，可从原账号重新读取云端报告；已有云端报告直接打开，不重复调用 AI。

未完成的作答进度只保留在当前设备；其他设备打开尚未完成的云端题库时从第一题开始。账号切换立即隔离草稿、进度、报告和云端列表，游客数据不会自动迁入账号。题库数量与筛选按云端统计，本机续答和待同步报告另行标注；网络失败时保留缓存并提供重试，已有本机完整报告可离线打开。设备存储失败时会提示，当前内存中的作答仍可继续。

新报告保存成功后会重新读取账号统计；已有资料请求尚未完成时，会在其结束后补读一次，避免显示报告保存前的旧 XP。刷新仍遵守账号隔离和昵称保存保护。

微信小程序使用平台登录；H5 默认游客模式。仅当 `TARO_APP_DEV_LOGIN=true` 且 API 地址为本机 `http://127.0.0.1` 或 `http://localhost` 时，“我的”提供明确标注的测试账号 A/B。正式微信登录还需要后端配置真实微信凭据。昵称支持保存到账号，头像展示后端返回的地址。前端不包含后端密钥。


编译器路径按实际安装位置调整。H5保留原型通配reset，小程序改用原生组件标签reset；颜色、间距和交互未另行设计。真机仍需单独配置并验证。
